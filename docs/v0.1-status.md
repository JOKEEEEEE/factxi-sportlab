# SportLab v0.1 — état au 5 août 2026

## Livré et vérifié

- Contrat modulaire `FootballDataProvider` indépendant du fournisseur.
- Premier adaptateur API-Football v3 pour les compétitions et les matchs.
- Configuration par variables d'environnement ; aucune clé n'est versionnée.
- Blocage avant connexion réseau lorsque `API_FOOTBALL_KEY` est absente.
- Modèle normalisé minimal : compétition, équipe, match, score et statut.
- Traçabilité par objet : fournisseur, endpoint, date UTC de collecte, périmètre,
  identifiants d'origine et description facultative du calcul.
- Tests hors ligne avec transport API simulé.
- Accueil SportLab avec huit compétitions, choix de saison, filtre par club et recherche.
- MatchLab historique : événements, courbes estimées, comparaison avant/après,
  statistiques, compositions, sources et limites.
- Courbe limitée aux buts et cartons rouges ; les autres événements restent dans le fil.
- Statistiques avec structure fixe pour première période, seconde période et match complet.
- Contrat éditorial versionné pour un carrousel de six images carrées 800 × 800.
- Générateur local de six PNG utilisant le logo FACT XI fourni.

Les cinq tests automatisés passent. Les pages HTML et le schéma JSON sont analysables sans
erreur. Aucun appel réel à API-Football ou à un LLM n'a été effectué.

## Partiel ou simulé

- Seul Arsenal–Manchester City est chargé et ses données proviennent de sources publiques.
- Les statistiques par période sont réservées dans l'interface mais restent vides : les
  rapports publics utilisés ne donnent que le total du match.
- Les probabilités de victoire sont un modèle explicatif de démonstration non calibré.
- Les textes du carrousel sont rédigés manuellement pour tester le contrat de sortie.
- Les écussons sont chargés depuis les ressources publiques de la Premier League.
- Le logo FACT XI est lu depuis le fichier local fourni dans `Downloads` ; il devra devenir
  un asset géré par l'application avant déploiement.

## Manque avant une v0.1 connectée

1. Fournir localement une clé API-Football et valider un premier appel contrôlé.
2. Confirmer la couverture réelle des statistiques par période, compositions, remplacements,
   cartons et événements VAR sur les huit compétitions ciblées.
3. Relier l'interface au client Python : les pages utilisent encore le jeu de démonstration.
4. Ajouter pagination, cache, stockage des réponses brutes et reprise après erreur.
5. Définir et calibrer le modèle de probabilités sur un historique ; la courbe actuelle ne
   doit pas être publiée comme statistique.
6. Brancher l'appel LLM sur un schéma de sortie strict, avec validation humaine avant rendu.
7. Intégrer durablement le logo, les écussons et les éventuelles photographies avec leurs
   droits d'usage et un mécanisme de repli.
8. Tester visuellement les exports PNG dans le navigateur cible et ajouter un téléchargement
   groupé lorsque le format final est validé.

## Pipeline cible immuable

`API-Football brut → normalisation → calculs déterministes → rédaction LLM structurée → contrôle humain → rendu 800 × 800`

Le contrat `editorial-schema.json` fixe le nombre de cartes, leur ordre, leur rôle et leurs
champs. Le LLM remplit ces champs mais ne modifie ni le DOM ni la géométrie du carrousel.
